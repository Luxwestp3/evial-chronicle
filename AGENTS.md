# Работа с архивом и сайтом

Эти правила действуют для всего репозитория.

## Источник истины

- Единственный источник истины о кампании — отслеживаемые файлы `content/`.
- Перед работой с кампанией прочитай [контекст](docs/campaign/CONTEXT.md), [соглашения архива](content/README.md) и [процесс](docs/campaign/WORKFLOW.md), затем относящиеся к задаче хроники и карточки.
- Исходные аудиозаписи лежат вне репозитория (`/Users/luxwestps/Documents/Projects/GitHub/Dungeons_Audios/`). Рабочие транскрипты, нарезка, модели диаризации и голосовые референсы живут в `private/` (в `.gitignore`) и никогда не коммитятся и не публикуются.

## Границы публикации

- Служебные документы и шаблоны — в `docs/campaign/`, инструкции — здесь. Не клади рабочие заметки внутрь `content/`.
- Редактируй только исходники. `.site-content/`, `public/`, `.quartz-cache/`, `quartz/static/evial-map.html` и мини-карты генерируются — не коммить и не правь их вручную.
- Рабочий сайт собирается из `.site-content/`:

```bash
node scripts/prepare.mjs
npx quartz build -d .site-content
```

Для локального просмотра добавь `--serve` ко второй команде. При изменении `content/` пересобирай `.site-content` через `node scripts/prepare.mjs`.

## Сборка и проверки

- Зависимости: `npm ci`, Node 22 ([.node-version](.node-version)).
- При правках кода/скриптов прогоняй `npm test`, `npm run check` и сборку сайта. `content/` и вендорный `quartz/static/leaflet` исключены из prettier.
- Не пушь в `main`, не сливай ветки и не запускай публикацию без явной команды пользователя.
