# Работа Codex с архивом и сайтом

Эти инструкции действуют для всего репозитория. Соблюдай границы текущей задачи:
обработка сессии не разрешает менять движок сайта, а обслуживание сайта — переписывать канон.

## Источник истины и порядок чтения

- Основной источник истины о кампании — отслеживаемые файлы `content/`.
  Внешний архив Claude и память предыдущего чата не заменяют содержимое репозитория.
- Перед работой с кампанией прочитай [контекст](docs/campaign/CONTEXT.md),
  [соглашения архива](content/README.md), [процесс](docs/campaign/WORKFLOW.md)
  и [решения](docs/campaign/DECISIONS.md), затем относящиеся к задаче хроники и карточки.
- Не дублируй канон в служебных документах: оставляй ссылки на архив.
  Неподтверждённые сведения и противоречия обрабатывай по `WORKFLOW.md`.

## Запрещённый старый импорт

**Не запускай `scripts/sync-archive.sh` в обычном рабочем процессе**, в том числе
перед сборкой. Он удаляет `content/` перед копированием внешнего архива.
Не вызывай его косвенно и не заменяй архив выгрузкой Claude.

Указание в [корневом README](README.md) о главном архиве Claude и команда синхронизации
в его примере устарели. Для Codex действуют эти инструкции: редактируй `content/` напрямую.
Отдельная задача на импорт требует предварительного сравнения с текущим архивом
и сохранения существующих исправлений; она не является частью обработки новой сессии.

## Границы публикации

- Служебные документы и шаблоны находятся в `docs/campaign/`, инструкции — здесь.
  Не помещай `AGENTS.md` или рабочие заметки внутрь `content/`: генератор может их опубликовать.
- Исходные транскрипты держи вне `content/` и `quartz/static/`.
  Порядок доступа и хранения описан в `WORKFLOW.md`.
- Редактируй исходники. `.site-content/`, `public/`, `.quartz-cache/`,
  `quartz/static/evial-map.html` и мини-карты генерируются; не коммить и не правь их вручную.
- Рабочий сайт собирается из `.site-content/`. `npm run docs` собирает каталог `docs/`
  и не является командой сборки сайта кампании.

## Сборка и обслуживание сайта

Установка зависимостей: `npm ci`. Версия Node указана в [.node-version](.node-version);
в [GitHub Actions](.github/workflows/deploy.yml) используется Node 22.
Сохраняй `package-lock.json` и существующие версии без задачи на обновление зависимостей.

Штатная сборка из корня репозитория:

```bash
node scripts/prepare.mjs
npx quartz build -d .site-content
```

Для локального просмотра добавь `--serve` ко второй команде. После изменения `content/`
заново выполни подготовку: Quartz наблюдает за `.site-content/`.

Перед изменением сайта прочитай затронутые исходники:
[конфигурацию](quartz.config.ts), [макет](quartz.layout.ts),
[подготовку контента](scripts/prepare.mjs), [стили](quartz/styles/custom.scss)
и [публикацию](.github/workflows/deploy.yml). В `quartz/` есть местные изменения;
сохраняй их при обслуживании. Учитывай подпуть сайта из `baseUrl` и ссылки в макете.

Для изменений кода запускай подходящие существующие проверки: `npm test`,
`npm run check` и сборку. Для документации проверь ссылки, форматирование изменённых
файлов и diff; для контента следуй `WORKFLOW.md`. Сообщай об имеющихся сбоях отдельно
от новых. Не запускай массовый `npm run format` ради посторонних файлов.

## Git и проверка результата

- Работай в отдельной ветке и готовь PR с описанием изменений и проведённых проверок.
  Не смешивай обновление кампании с обслуживанием движка без явной задачи на оба вида работ.
- Проверяй `git diff` и состав файлов перед коммитом. Не включай исходные транскрипты,
  секреты, рабочие материалы мастера или генерируемые файлы.
- Пуш в `main` и ручной запуск workflow могут опубликовать сайт. Не пушь в `main`,
  не сливай PR, не включай автоматическое слияние и не запускай публикацию без явного
  поручения пользователя на соответствующее действие.
